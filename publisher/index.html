    Publisher guide
    
            
        
    

        
    

            
    1 · Publish a post in five steps
    

            
      
                
    1. Start. Click 📅 Start next month’s post. The date, byline and
                    categories fill in from your monthly template, using the next month that has no post.
      2. 
                
    2. Write. Copy your article in Word and paste it into step 3.
                    A green note confirms what arrived — “Formatting kept from your document —
                    8 headings, 31 paragraphs, 18 bullets.”
                    If it says 0 or 1 headings, stop and check the preview. Something did not
                    survive the paste.
      3. 
                
    3. Add the image. Drop your Canva export into step 4. It is resized to 1600px and
                    converted automatically — a 2 MB PNG becomes roughly 140 KB. Do not resize it yourself.
      4. 
                
    4. Check the preview. The right-hand panel renders the finished page with the real
                    stylesheet. Confirm the headings are bold and the paragraphs are separated.
      5. 
                
    5. Generate, then publish. Press Generate the publish bundle, then run the
                    command from the Files tab in Terminal. Live in about a minute.
      6. 
            
    

            
    Editing a post you have already written? Use Edit published in step 2, and
                press ↻ Regenerate from the article under the card summary after a rewrite — the
                summary keeps its old text otherwise, and that text is what appears on the blog card, in Google and in
                the LinkedIn preview.
    

            
    2 · How your files reach GitHub
    

            
    This dashboard never touches GitHub. It holds no password and has no connection to it.
                It only prepares files. There are two routes:
    

            
    
                
    
                    Folder connected (Chrome)
                    Generate writes the files straight into your repository folder. No download.
                
    
                
    
                    Not connected, or Safari
                    Generate gives you a .zip; the publish script finds and unpacks it.
                
    
            
    

            
    Either way, ./publish.sh does the committing and pushing, and deletes the bundle once it has
                been published.

    4 · The LinkedIn tab — what it does not do
    

            
    It does not connect to LinkedIn. There is no login, no authorisation, no automatic
                posting and no cross-posting. Nothing is sent anywhere.
    

            
    It is a writing aid. It shows two things for you to copy by hand:
    

            
      
                
    • Page URL — your article’s address, with a Copy button
      • 
                
    • Draft post — the headline, your summary, a line pointing at the article, the
                    URL, and hashtags built from your categories
      • 
            
    

            
    Copy it, open LinkedIn yourself, paste, edit and post. Put the URL on its own line: LinkedIn builds the
                preview card from your page’s title, description and image, all of which are written into the page
                automatically.
    

            
    5 · Troubleshooting
    

            
    
                
    A change I made is not showing
    
                
    GitHub caches pages for ten minutes. Hard-refresh with Cmd+Shift+R,
                    or add ?v=2 to the address. Use one browser — switching between Chrome and Safari
                    shows you two different cached versions.
    

                
    “Support for password authentication was removed”, or the push is refused
    
                
    GitHub wants a token, not your password. Create one at
                    github.com/settings/tokens
                    → Generate new token (classic) → tick repo. At the prompt the
                    username is jotaigbe2026 and the password is the token. Your keychain remembers it.
    

                
    “Updates were rejected… non-fast-forward”
    
                
    Something else pushed first, usually the automated monthly featured-article job. Run
                    git pull --no-rebase origin main, resolve anything it flags, then run the publish script.
                    Never force-push.
    

                
    fatal: not a git repository
    
                
    Terminal opened in your home folder. The cd is part of the command — paste the
                    whole line, not just the last part.
    

                
    I ran the command and nothing happened
    
                
    You pasted into a window that is already running something, such as the preview server. Open a new
                    Terminal window with Cmd+N.
    

                
    My post vanished from the queue and the Edit list
    
                
    It is on your Mac but not on GitHub. Run git status; if it reports commits ahead, run
                    the publish script.
    

                
    The preview is blank
    
                
    An empty form previews an empty article. Load a post with Edit published, or start typing.
    

                
    I cannot find the preview
    
                
    On a narrow window it moves below the form. Widen the window, or press 👇 Preview.
    

                
    I deleted something by accident
    
                
    Nothing is ever lost. Every version of every file is kept in the repository’s history and can be
                    restored exactly, including posts, images and PDFs.
